# AI 해설 실험 (2026-10)

로그 분석 결과를 AI 가 한국어 보고서로 풀어 설명하는 웹앱을 붙여 본 실험.
Hugging Face 를 공부하며 진행했고, 결과를 보고 탐지 도구에는 넣지 않기로 함.

## 파일

| 파일 | 내용 |
|------|------|
| `streamlit_app.py` | 웹앱 화면 (로그 업로드 → 규칙 기반 탐지 결과 + AI 해설) |
| `ai_report.py` | AI 에 보낼 보고서·프롬프트 생성, 모델 답 정리 |
| `test_ai_report.py` | `ai_report.py` 테스트 |
| `requirements.txt` | 웹앱용 라이브러리 (streamlit, huggingface_hub) |

## 구조

- 판정은 `log_analyzer.py` 의 규칙이 하고, AI 는 그 결과를 설명만 함. AI 가 틀려도 판정은 바뀌지 않음
- AI 엔진 두 가지
  - HF API: Hugging Face Inference Providers 서버의 모델 (기본값 `Qwen/Qwen3.5-9B`)
  - 로컬: 노트북에 `Qwen/Qwen2.5-1.5B-Instruct` 를 내려받아 실행 (torch·transformers)
- 보안 처리
  - 로그 문구는 공격자가 조작할 수 있는 데이터로 보고, 시스템 프롬프트에 그 안의 지시를 따르지 말라고 명시
  - 로그에 심은 ` ``` ` 로 코드블록을 일찍 닫아 지시문을 끼워 넣지 못하도록 백틱을 치환
  - 길이 제한(6000자)에 걸려도 판정 근거가 남도록 경고를 앞에, IP 목록을 맨 뒤에 둠

## 결과와 배운 점

- 무료 계정으로는 HF API 로 모델을 쓸 수 없었음 (Inference Providers 는 크레딧 필요)
- 로컬 1.5B 모델은 동작했지만 해설 품질이 도구에 붙여 쓸 수준이 아니었음
- 모델이 답을 만드는 과정(토큰화 → 채팅 템플릿 → 생성)과 모델을 로컬에서 실행하는 방법을 익히는 연습으로 마무리함

## 도구에 넣지 않은 이유

- 실제로 쓸 수 있는 엔진이 없음 (API 는 크레딧 필요, 로컬 모델은 품질 부족)
- 동작하지 않는 기능을 남겨두면 처음 보는 사람이 실패 메시지만 보게 됨
- 규칙 기반 판정만으로 도구의 목적을 충족하고, 웹앱·AI 의존성(streamlit, huggingface_hub, torch)은 그에 비해 관리 부담이 큼

## 유의사항

- 2026-10 당시 코드를 그대로 보존한 기록. `log_analyzer.py` 가 바뀌어도 맞춰 고치지 않으므로 나중에는 그대로 실행되지 않을 수 있음
- 다시 실행하려면 이 폴더의 파일을 저장소 최상위로 옮기고 `requirements.txt` 를 설치해야 함. HF API 엔진은 `.streamlit/secrets.toml` 에 `HF_TOKEN` 이 필요함
