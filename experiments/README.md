# 브루트포스 임계값 실험 (2026-08-09)

정상 사용자와 공격자를 가장 잘 구분하는 기준치를 찾기 위해 진행한 실험 기록.
탐지 도구 본체와는 별개이며, 결과는 당시 임계값을 정하는 근거로 사용함.

## 파일

| 파일 | 내용 |
|------|------|
| `gen_log.py` | 정답(정상/공격)이 정해진 가짜 로그 생성기 |
| `test.log` | `gen_log.py`가 만든 로그 (88줄) |
| `r3.txt` ~ `r8.txt` | `test.log`를 기준치 3·5·6·8회(10분 창)로 분석한 보고서 |
| `r10.txt` | `sample.log`를 기준치 10회로 분석한 보고서로 보임 (파일명과 내용으로 추정) |

## 방법

1. `gen_log.py`로 로그 생성. 시드(42)와 기준 시각이 고정되어 있어 실행할 때마다 같은 로그가 나옴
   - 정상 사용자 12명: 8분 안에 1~5회 실패 (`NORMAL_MAX_FAILS = 5`)
   - 공격자 3명: 9분 안에 8회 실패 2명, 3분 안에 40회 실패 1명
2. 당시 CLI의 단일 기준치 옵션(`--threshold`, 10분 창)으로 3·5·6·8회 각각 분석
3. 경고가 정상 사용자에게 나갔는지(오탐), 공격자를 놓쳤는지 확인

## 결과

| 기준치 | 정상 사용자 오탐 | 공격자 탐지 (3명 중) |
|--------|------------------|----------------------|
| 3회 | 6건 | 3명 |
| 5회 | 3건 | 3명 |
| 6회 | 0건 | 3명 |
| 8회 | 0건 | 3명 |

정상 사용자의 최대 실패 횟수(5회)보다 큰 6회부터 오탐이 사라지고, 공격자는 모두 탐지됨.
이 결과로 기준치를 6회로 조정함 (커밋 `e8f1631`). 이후 급속·완속 2단계 탐지로 바뀜 (커밋 `fc0b6a2`).

## 유의사항

- `r*.txt`는 당시의 단일 `--threshold` 옵션으로 만든 결과. 현재 CLI는 `--fast-threshold`·`--slow-threshold`를 쓰므로 같은 명령으로는 재현되지 않음
- 가짜 로그 기준의 결과이므로 실제 서비스 로그의 분포와는 다를 수 있음
- 설계 문서(`docs/superpowers/specs/2026-08-09-tiered-bruteforce-detection-design.md`)에 적힌 생성기 구성(4개 그룹, IP를 돌려 쓰는 공격자 등)은 계획안이며, 실제 `gen_log.py`는 위 방법대로 구현됨

## 로그 다시 만들기

```bash
python3 experiments/gen_log.py
```

어디서 실행해도 `experiments/test.log`에 만들어지고, 화면에 정답지(IP별 정상/공격 구분)가 출력됨.
